# 統合マクロ解析の実行計画

**Goal:** 既存データだけを使い、固定した二時点の繁殖分布集中を中心に一本の論文へまとめる。

**Architecture:** 元計数 → 原本・階層台帳 → 同期した二時点・固定構成単位 → 共通の集中／個体数変化 → 凍結した形質・気候 → 方向を固定した関連モデル → 固定分布の将来曝露。元結果と凍結原稿は保持する。

**Tech stack:** 既存Gitブランチ `codex/climate-penguin-progress`、保存済みCSV/XLSX/JSONと既存Python/JavaScript処理系。列契約はJSON Schema、説明と解析契約はMarkdown。関連モデルの実装・パッケージ版はStep 3凍結時に記録する。

**Spec:** [STEP1_TABLE_SPEC.md](STEP1_TABLE_SPEC.md)、[PREREGISTRATION_DRAFT.md](PREREGISTRATION_DRAFT.md)、[SCHEMA.json](SCHEMA.json)、[SOURCE_CATALOG.json](SOURCE_CATALOG.json)。

## 現在地と制約

**現在の主目標はStep 1。** このコミットは設計・事前分析計画の草案であり、統合効果量の計算完了を意味しない。既存結果の確認、入力所在と原本識別子の整理、表・帰無・重複の仕様、Q2–Q4の方向案までを整えた。

同じ既存ブランチ／Draft PR #206で進める。新しいデータ系列、追加の生態学的研究線、食性・カメラ・GPSの主モデルへの追加は行わない。現ブランチにない**同じ固定原本**の回収は新しいデータの導入と区別する。既存原本も回収できなければ、代替出典や短い期間へ無断で切り替えず、未推定行と不足範囲を残す。既知結果を未閲覧の事前登録として表示しない。

## 今やること：Step 1　共通表を作る

ユーザーの目安は1–2日。以下は実装単位であり、所要時間の保証ではない。

1. **入力と系統を固定する。**
   - [x] 現ブランチのMAPPPD、皇帝、Ross、短いローカル表を確認し、別ブランチのJNCC固定コミットを特定する。
   - [x] [SOURCE_CATALOG.json](SOURCE_CATALOG.json)に既存原本のSHA・場所・不足項目を記録する。
   - [ ] JNCC原XLSX、Palmerのcolony-code原本、Signyの1996–2019年原本を既存の識別子から回収し、SHA一致を確認する。
   - [ ] `SOURCE_CATALOG.json`の回収状態と親子・同一計数の対応を更新する。原本の回収は数値変更の許可ではない。
2. **二時点と集合を先に固定する。**
   - [ ] 出力先 `data/endpoint_registry.json` に全候補、同期年、固定単位、方法、除外理由を保存する。Q4の種ペアも独自の共通期間・共通物理集合を固定する。
   - [ ] `data/unit_endpoints.csv` を元行へ逆引きできる形で作り、元計数と欠測・観測0・原計数単位を確認する。
   - [ ] 時点台帳のSHAを保存してから共通集中効果量を計算する。既存の結果を見たことは記録に残す。
3. **共通効果量を計算する。**
   - [ ] 固定した計数表だけから `data/network_species.csv`、`data/network_species_pairs.csv` を作る。列は[SCHEMA.json](SCHEMA.json)に従う。
   - [ ] B=20,000の共通計数帰無を適用可能な行に実行し、モデル指数・終点0・非同期・原本未回収の行は理由付きNAにする。
   - [ ] 皇帝はN_meanからの配分点推定だけを保存する。モデル平均の整数化や周辺区間の独立乱数化は行わない。
4. **一枚の読める表と品質確認を出す。**
   - [ ] `outputs/STEP1_READOUT.md` に全対象数、推定可能数、解析役割、期間、単位、K、N、集中、個体数変化、幅を掲載する。
   - [ ] 元計数との合計一致、K固定、終点0保持、日付同期、重複排除、ペア共通集合、帰無の再現性を検証する。
   - [ ] 主表の全候補数と、各検定で使える数を分ける。旧解析の1,321行・17種やMAPPPDの32候補を新解析の完成Nとして使わない。
